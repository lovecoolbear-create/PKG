成本分析 · 逻辑与方法论文档

适用范围：彩印纸盒（color_print_box） 版本基线：提交 24985af 之后 5 维 + 只读审阅器 + 真实案例校准闭环已规划

目的：让任何接手的人（包括未来你自己）能看懂这套成本引擎「怎么算、为什么这么算、哪里不可信、后期怎么调准」。

1. 系统架构

整体采用 「dataflow 单源派生 + 多 Agent 只读计算 + 只读审阅」 的确定性架构（非 LLM 自由推理）。

用户填写参数 (AnalysisInput) │ ▼ [applyDefaults] 补默认值 + 收集「默认假设」清单 │ ▼ [loadKnowledgeBase] 预热知识库（材料价/工艺费率/地域费率），失败静默回退常量 │ ▼ [deriveAnalysisContext] ←── 只算一次所有共享派生量（面积/数量/损耗率/盒型/坑型…） │ （dataflow：消除重复计算、单一真相源） ▼ [runAllAgents] 并行调用 5 个只读 Specialist ├─ materialAgent 材料成本 ├─ laborAgent 人工成本（仅人工随地域浮动） ├─ processAgent 加工费（含设备，不随地域浮动） ├─ designAgent 设计与制版成本 └─ financeAgent 财务与其他成本（入参 = 前四项汇总 + 设计） │ ▼ [calculateRatios] 算各维度占比；[validate] 占比区间/完整度/置信度校验 │ ▼ [reviewAnalysis] 只读跨维度审阅（**绝不改数字**） │ ▼ [report] 汇总：总额/区间/单只价/置信度/假设透明化/优化建议/SQE 诊断
设计原则（来自架构决策）
  • 禁止在 Agent 间引入自由迭代 loop（数值正反馈振荡、无收敛判据、破坏可追溯）。
  • 允许的唯一「非零通信」 = 共享派生上下文（dataflow）：一次算好、只读消费。
  • 审阅器只产出 findings，不回写、不重算。

4. 各维度计算逻辑（Agent 公式）

4.1 材料成本 materialAgent

pieceFactor   = boxType.pieceCount           // 天地盖=2(lid+base)，其余=1
faceGrammage  = 天地盖 ? 157g(薄面纸) : 所选克重
weight        = calculatePaperWeight(area×pieceFactor, faceGrammage, 数量,
                                      {wasteRate:lossRate, impositionUtilization:util})
             = imposedAreaM2 × 克重/1000 × 数量 × (1+损耗率)
pricePerTon   = 实时抓取价 → 知识库 → 静态 MATERIAL_PRICES
discount      = getQuantityDiscount(数量)     // ≥5万0.85 / ≥2万0.88 / ≥1万0.92 / ≥5千0.95 / ≥1千0.98 / 1.0
面纸金额      = weight × pricePerTon/1000 × discount

if 瓦楞(flute≠none):
    坑纸金额   = calculatePaperWeight(同公式, flute.fluteGrammage) × 坑纸单价/1000 × discount
    裱坑加工   = imposedAreaM2 × 数量 × FLUTE_MOUNTING_RATE(0.18)
if 天地盖(rigid):
    灰板金额   = calculatePaperWeight(同公式, 1000g灰板) × 3800/1000 × discount

amount = 面纸 + 坑纸 + 裱坑 + 灰板
confidence = 80(数量>0且材质已填) / 55
amountRange = [amount×0.92, amount×1.08]

4.2 人工成本 laborAgent（独立维度）

⚠️ 简化模型（非真实工时核算）：人工按「固定元/个 × 复杂度 + 糊盒 + 换线固定工时」估算，并非逐工序「工时 × 小时费率」的精确工资核算，仅作量级参考。真实人工以校准案例记录为准（见 calibration-cases.example.json 的 actualLabor）。
regionMultiplier = getRegionMultiplier(laborRegion)   // 华东基准 1.0，仅作用于人工
regionHourlyRate = getRegionRate(laborRegion)          // 地域小时费率（华东 28，可 KB 覆盖）
baseLabor   = 数量 × LABOR_BASE_PER_PIECE(0.05) × boxType.complexityMultiplier
gluingCost  = 需糊盒 ? 数量 × LABOR_GLUING_PER_PIECE(0.025) : 0
setupLabor  = LABOR_SETUP_ENABLED ? LABOR_SETUP_HOURS(0.5) × regionHourlyRate : 0   // 换线/调机固定人工
amount      = (baseLabor + gluingCost) × regionMultiplier + setupLabor
confidence  = laborRegion有值 ? 72 : 55
amountRange = [amount×0.9, amount×1.15]

4.3 加工费（含设备） processAgent

展示拆分：加工费在报告中按 kind 拆分列示——「纯工艺加工费」（印刷运行费/油墨/表面处理/模切/贴窗）与「设备·开机相关费用」（开机托底 + 专色调色洗车 + 刀模费一次性）。计算逻辑不变，仅展示分组；若某单无独立设备/开机固定费，注明「开机费已含入印刷运行费」。
totalColors   = cmykColors + spotColors
printRate     = 印刷方式单价(元/色/千印)：offset 35 / digital 80 / flexo 25
printCost     = (数量/1000) × printRate × totalColors
              → 非数码且 < PRINT_MIN_CHARGE(350) 时托底为 350（开机费）
spotSetupCost = spotColors × 150(调色/洗车费)
windowFilm    = 数量 × boxType.windowFilmCostPerPiece(开窗盒 0.05)
coverage      = 烫金/凹凸 ? getSurfaceCoverage(level, surface, override) : 1
              // 局部覆盖率：默认 medium=8%；可选 low=4%/high=15%；
              // surfaceCoverageOverride(0~1) 预留「由稿件自动估算」接口，优先于等级
surfaceRate   = 表面处理单价(元/m²)：哑膜0.45/亮膜0.42/UV1.2/烫金3.5/凹凸2.0/无0
surfaceArea   = coverage<1 ? netAreaM2 : imposedAreaM2   // 全覆盖用拼版后面积，局部用净面积
surfaceCost   = surfaceArea × 数量 × surfaceRate × coverage
dieCutCost    = 数量 × 0.015
dieFormCost   = DIE_FORM_COST(200)            // 一次性刀模费
amount = printCost + spotSetupCost + windowFilm + surfaceCost + dieCutCost + dieFormCost
confidence = 印刷方式且表面处理已填 ? 78 : 50
amountRange = [amount×0.9, amount×1.12]

4.4 设计与制版 designAgent

plateCost    = 数码 ? 0 : cmykColors×350 + spotColors×450(专色版更贵)
designCost   = 客户提供完稿 ? 0 : 800
proofingCost = 数量<5000 ? 300 : 150
amount = plateCost + designCost + proofingCost
confidence = 印刷方式已填 ? 75 : 50
amountRange = [amount×0.9, amount×1.05]

4.5 财务与其他 financeAgent（入参 = 前 4 维汇总 + 设计）

logisticsRate   = 按交付地：华东0.03/华南0.035/华北0.04/华中0.038/西南0.045/东北0.042
logisticsCost   = subtotal × logisticsRate
packagingCost   = 数量 × 0.008
managementCost  = subtotal × 0.06
urgencyMult     = 标准1.0 / 加急1.15 / 特急1.3
profitBase      = (subtotal + logisticsCost + managementCost) × 0.08
urgencyPremium  = urgencyMult>1 ? subtotal×(urgencyMult-1)×0.5 : 0
amount = logisticsCost + packagingCost + managementCost + profitBase + urgencyPremium
confidence = 交付地已填 ? 72 : 55
amountRange = [amount×0.9, amount×1.15]

6. 知识库与回退机制

loadKnowledgeBase() 每次分析开头 await 一次，把 DB 的 KnowledgeEntry 预热进内存单例。

读取层提供 getMaterialPrice / getFlutePrice / getProcessRate / getRegionRate / getRegionMultiplier / getLogisticsRate，统一逻辑：

  1. 优先从知识库条目取值（fromKb: true）；
  2. 取不到（库未初始化/查询失败/条目缺失）→ 回退代码常量（fromKb: false）；
  3. DB 加载失败时记 loadFailedAt 并进入 60s 冷却，冷却期内不再打 DB，冷却结束自动重试（避免永久静默退化）。
含义：真实部署配了知识库价格表，引擎自动用真实价；没配则全程走常量，功能不崩。

7. 置信度与默认假设（透明化）

  • 默认值：FIELD_DEFAULTS 对未填字段套用行业合理默认（如 350g、胶印、哑膜、华东），并收集「默认假设」清单，在报告中独立透明展示。
  • 置信度下调：getDefaultPenaltyForDimension = min(命中默认字段数 × 8, 25)，叠加到各维度与整体置信度。
  • 人工地域回退：未显式选生产地域时，自动回退到交付地（deriveAnalysisContext），避免地域系数静默恒为 1.0。

8. 校验与审阅

  • validate()：维度占比越界（±5% 容差）、信息完整度 <60%、单 Agent 置信度 <60% → warning。
  • reviewAnalysis()（只读）：材料主导提示、烫金/凹凸 8% 局部覆盖率提醒、单只成本 <0.05 或 >50 元异常提示、维度齐全性检查。产出 consistent 标志与 perUnitEstimated。

⚠️ 缺失MOQ/良率/拼版跨单摊销最小起订量约束、良率报废、跨订单拼版摊销均未纳入

定位：作为一期「快速估算 + 谈判辅助」已够用且显专业；要进入二期 VAVE（量价曲线、纸价冲击）和三期（供应商落地、真实报价闭环），最该补的是用真实成交价做偏差校准。

10. 示例演算

验证用，彩盒 200×150×80 / 5000 / 白卡350 / 胶印4C / 哑膜 / 糊盒 / 扣底盒 / 华东：

展开面积 = 2(200×150+200×80+150×80) + 80×15 + 200×20×2 = 125200 mm²
净面积 = 0.1252 m²/个；拼版后 = 0.1252/0.85 = 0.1473 m²/个
损耗率 8%（5000<1万）；折扣 0.95（5000）

材料：weight=0.1473×350/1000×5000×1.08=278.4kg；价5600元/吨
     → 278.4×5.6×0.95 = 1481 元
人工：5000×0.05×1.0 + 5000×0.025 + 换线0.5h×28 = 389 元（华东系数1.0；简化模型非真实工时核算）
加工：印刷 (5×35×4)=700；哑膜 0.1473×5000×0.45=331；模切75；刀模200 = 1306 元
设计：4×350 + 800 + 150 = 2350 元
财务：(1481+375+1306+2350)=5513 小计
     → 物流165 + 包装40 + 管理331 + 利润481 = 1017 元

总额 ≈ 6529 元；单只 ≈ 1.31 元/个
注意：本例设计占比 ~36%，远超预期区间 [3%,10%]——因为设计/制版是固定费，在 5000 批量下占比天然高，校验会给出 warning，属真实现象。这也说明「预期占比区间」更适合中大批量，小批量看绝对值。

11. 后期如何攒案例校准（四阶段闭环）

核心结论：引擎结构已稳，差的是「真实成交价」这个数据底座。完善路径是「攒案例 → 自动比对偏差 → 反推常数 → 系统化数据源」的迭代闭环。

阶段 0 — 攒真实案例（你来做，我不动）

每收到一张工厂报价单，按统一模板追加到 calibration-cases.json（模板见 calibration-cases.example.json）：

{
  "caseId": "2026-客户A-彩盒",
  "input": { "length":200,"width":150,"height":80,"quantity":5000,
             "material":"white_card","grammage":"350","printMethod":"offset",
             "colorCount":"4","surfaceTreatment":"matte_laminate","needGluing":true,
             "boxType":"tuck_end","laborRegion":"east_china","deliveryLocation":"east_china" },
  "actual": { "total":6800,"material":2900,"labor":520,"process":1500,
              "design_plate":700,"finance_other":1180 },
  // 必填：工厂实际人工金额及构成，用于对比简化模型偏差、反推常数
  "actualLabor": { "total":520,"unit":0.104,"hours":18,"hourlyRate":28,
                   "headcount":2,"setupHours":0.5,
                   "note":"计件+计时混合；含换线0.5h；华东厂" },
  "meta": { "supplier":"某厂","date":"2026-08","note":"含16%税" }
}

起步攒 10–20 单（覆盖彩盒/瓦楞/精品盒/不同地域）即可跑第一轮。

阶段 1 — 校准脚本吃真实数据（我来做）

把 scripts/calibration-test.ts 从「硬编码经验价带」改为「读 calibration-cases.json」，自动算 引擎 vs 实际 的总单价偏差 + 分维度占比偏差，标红越界项。

阶段 2 — 反推常数（我来做）

哪维度系统性偏离 → 定位对应常数（纸价表 / 损耗率 / 地域系数 / 设计费 / 印刷单价等）→ 调后重跑，直到偏差收敛到 ±10% 内。即「逐步完善」的迭代闭环。

阶段 3 — 系统化数据底座（路线图三期）

纸价行情 API、多地域费率、企业历史成交价库，替换静态假设；图纸 → RFQ → 回收报价闭环。

你唯一要做的：按模板攒案例。攒到一批喊我，我接阶段 1 + 阶段 2。

> 文档用途：对齐团队 PCO 蓝图与本工具现状，定义 VAVE 模块的信息架构、数据桥、最小闭环范围与分期路线。
> 最后更新：2026-08-24
> 关联：PROJECT_STATUS.md（§6 路线图）、成本分析逻辑与方法论.md、团队 PCO 五份规划文件

## 1. 目标与定位

VAVE（Value Analysis / Value Engineering）模块是「包装降本分析工作台」的**二期能力**，与一期成本分析**同应用、独立模块、共享数据**。

- **不是**另起一个独立工具（避免引擎双份维护、数据漂移、体验割裂）。
- **是**双入口工作台：成本分析与 VAVE 各有独立入口，但 **VAVE 的基石永远是成本分析输出（AnalysisReport）**（见 §3 选项 B 解析）。客户无论走哪条入口，最终都先有一份成本分析，再在其上生成 VAVE 报告——不是「先做成本 or 先做 VAVE」二选一，而是「VAVE 必建在成本分析之上」。
- **联动**：成本分析结果可物化为「项目」，VAVE 在需要联动时一键带入，不重算、不丢上下文；反向可点「看成本明细」回链。

团队 PCO 蓝图（PDR V2.0 / 系统架构决策 / 销售策略）已明确产品形态为「包装供应链 AI 降本平台」，本模块即其工作台落地。

## 2. 设计原则（采纳 PCO 架构决策 B）

团队「系统架构方案对比与决策报告」已拍板 **方案 B（改进版）胜出**（11 维中胜 8，73%）：

> **分析层全量客观 + 展示层按 KP 三级裁剪。** 一次分析产出结构化结果，按部门/职级裁剪多份视图，避免方案 A「身份先行」导致的跨维度遗漏与数据不一致。

本模块完全采纳方案 B，并具象为：

| 层 | 职责 | 现状 |
|---|---|---|
| 分析层（客观） | 成本引擎产出 `AnalysisReport`（五维金额、占比、理论面积/利用率、成本驱动、优化建议），**不带任何 KP bias** | ✅ 已落地 |
| 展示层（裁剪） | VAVE 按场景/KP 重新组织同一份结果：采购看成本结构+让利空间，研发看设计优化点，高管看总降本潜力 | 🟡 本期建设 |

> UI 落地形态即上轮确认：「双入口工作台 + 共享项目上下文」。

**两层边界（关键）**：成本引擎是**确定性单遍**计算（6 specialist 纯规则、禁互调 loop，见 §5.1）；VAVE 策略报告是**LLM 多 Agent 协作层**，只读消费引擎输出。多 Agent 出现在 VAVE 策略层是合理且必要的（见 §5.1），但绝不进入成本计算层——这是此前架构决策「禁 specialist 互调」与「VAVE 需多 Agent」两者不冲突的根本原因。

## 3. 信息架构（双入口工作台）

```
包装降本分析工作台（/）
├─ 项目/案例列表（成本结果可保存为「项目」）
├─ [成本分析] 入口 → /analyze（已有）
│     产出：结构化 AnalysisReport → 保存为「项目」
└─ [VAVE 降本] 入口 → /vave（新增）
       ├─ 选项 A：基于已有项目（联动，一键带入 /analyze 成本结果）
       └─ 选项 B：独立新建（在 /vave 内录入参数或上传报价单 → 内部跑一次引擎 → 生成 AnalysisReport → 进入 VAVE）
```

**数据依赖（关键）**：VAVE 策略层与敏感性/谈判辅助**必须消费 `AnalysisReport`**，因此「独立新建」并非跳过成本分析，而是把成本分析作为 VAVE 的第一步在 /vave 内隐式完成。两模块**路由独立、UI 独立**，但**数据上 VAVE 永远建立在成本分析之上**（用户 2026-08-24 决策：要求客户先做成本分析，再进 VAVE）。

**联动实现（数据桥，见 §4）**：VAVE 打开时弹「基于现有项目 / 新建」，选了就直接吃成本结果做敏感性/谈判模拟，不重算、不丢上下文；反向可点「看成本明细」回链。

## 4. 数据桥（核心前置）

### 4.1 现状缺口

当前成本分析是**无状态前端会话**（输入存页面 state，刷新即丢），尚无「项目」实体。**要做联动，必须先补轻量「项目/案例」存储**——这是真正的技术前置，不是 UI 皮。

### 4.2 项目实体（Project/Case）

VAVE 消费的结构（由成本引擎 `AnalysisReport` + 原始 `AnalysisInput` 物化而来）：

```ts
interface CostProject {
  id: string;
  name: string;                 // 客户/产品名，用户填
  createdAt: string;
  // 原始输入（用于重算敏感性）
  input: AnalysisInput;
  // 成本引擎客观输出（快照）
  report: AnalysisReport;
  // ⚠️ summary 不落库，读取时由 report 派生（见下方说明），避免与 AnalysisReport 字段漂移
}
```

> **`summary` 为派生视图，不存储**：VAVE 读取项目时由 `report` 现场计算——
> - `totalCostPerUnit` ← `report.totalCost.perUnit`
> - `dimensionRatios` ← `report.dimensions[].ratio`（键为维度 code）
> - `costDrivers` ← `report.costDrivers`（前 3 驱动，AnalysisReport **顶层**字段，非 summary 下）
> - `optimizationHints` ← `report.optimizationHints`（顶层字段）
> - `areaMetrics` ← `report.dimensions.find(d => d.dimension === "material")?.areaMetrics`（材料维挂载，非顶层）

**存储选型**：
- 一期 MVP：浏览器 `localStorage`（零后端改动，快速验证联动体验）。
- 落库（Prisma/SQLite）：归三期，与「外部纸价 API / 多地域费率 / 分享链接」同批推进（见 §8 三期清单），不在二期重复列项。

### 4.3 数据流

```
/analyze 产出 AnalysisReport
   → 用户点「保存为项目」→ CostProject 落 localStorage
   → /vave 选该项目 → 直接读 report + input
       ├─ 敏感性：用修改后的 input 重跑 `runOrchestrator`（全 fan-out，纯函数确定性强）→ 对比曲线
       └─ 谈判辅助：读 summary → 生成目标价/让利空间/话术
```

## 5. VAVE 策略层与最小闭环

**原则：只建在已落地的五维成本数据之上，不依赖任何新数据源。** 策略报告由「多 Agent 协作」生成（LLM 层），敏感性/谈判辅助为确定性能力（引擎层）。

### 5.1 VAVE 策略层多 Agent 协作架构

VAVE 的 15 维策略报告采用**多 Agent 协作**：一组「维度策略 agent」各自只读消费同一份 `AnalysisReport`，再由一个「全局合成 agent」合并出全局一致报告。

```
成本引擎（确定性单遍，不变）
   → AnalysisReport（客观结构化结果）
   → 多个「维度策略 agent」（并行，只读）
        ├─ 技术层策略 agent（维度 1-5：结构/装载/工艺/材料替代/工效）
        ├─ 采购层策略 agent（维度 6-10：溢价/集采/半径/资金/ESG）
        └─ 补充层策略 agent（维度 11-15：质量/库存/标准化/风险/废弃物）
   → 「全局合成 agent」（1 个）
        合并各维 → 解跨维冲突 → 出全局一致 VAVE 报告
```

**为什么多 agent 而非单 agent**：材料降本、工艺替代、ESG 是差异很大的领域，单 agent 一次调用会浅而泛；拆开能各自深做、并行跑、各自标注数据来源。而「符合全局」靠最后的合成 agent 保证——它专门处理跨维冲突（如"材料降本 vs 质量过度包装""设计标准化 vs 定制化"），单 agent 给不出这种一致性。

**与成本引擎的边界（不踩坑）**：
- 禁止：6 个成本 specialist 互相重算（数值振荡、无收敛、不可追溯）——仍禁止。
- 允许：VAVE agent 是**独立工作台**，只读消费引擎 OUTPUT，不串 6 specialist 内部 loop，符合 §5.1「禁互调 loop」约束。

**LLM 多 agent + 模板兜底**：配 LLM 时走多 agent 协作；未配 LLM（与现有引擎 fallback 机制一致）走模板规则生成，功能不阻塞。

### 5.2 敏感性分析
| 能力 | 输入变化 | 引擎复用 | 产出 |
|---|---|---|---|
| 量价曲线 | 变动 `quantity` | 重跑 → design(固定费摊薄)/labor/finance 随量变 | 单只成本随量下降曲线 + 盈亏平衡点 |
| 纸价冲击 | 变动材料单价（知识库/手动） | 重跑 materialAgent | 材料成本占比变化、总价敏感度 |
| 工艺替代对比 | 切换工艺路线 | processAgent breakdown(kind=process/equipment) | 不同工艺路线成本对比 |

### 5.3 谈判辅助
| 能力 | 数据来源 | 产出 |
|---|---|---|
| 目标价反推 | 给定客户目标价 + 由 `report.dimensions[].ratio` 派生占比 | 各维可压缩空间拆解 |
| 让利空间 | `report.totalCost.perUnit` + `report.costDrivers` | 保本价、最大可让利百分比 |
| 谈判话术 | `report.costDrivers` + `report.optimizationHints` + 材料维 `areaMetrics.utilization` | 「材料占 X%，纸价波动是主风险」「设计利用率仅 Y%，有 VAVE 空间」等话术模板 |

### 5.4 设计空间利用率（已埋伏笔）

材料维 `areaMetrics.utilization`（理论使用面积占比）直接对应 PCO 维度 1「结构设计优化」——给客户看「你的盒型材料利用率仅 60%，40% 是废边，VAVE 可优化」，是专业感与二期抓手的最佳落点。

## 6. 展示层角色决策策略（商业策略核心）

> **关键定性**：展示层不是「同一份数据换种排布」，而是 agent **主动决策**——
> 基于读者岗位/职级，决定哪些问题**重点强调**、哪些**降权弱化**、哪些**屏蔽或改写后不出现**。
> 这正是团队《全 KP 岗位销售策略手册》四维杠杆（KPI 赋能 → 安全感 → 权力保护 → 成交路径）起作用的地方。

### 6.1 角色选择器（谁在读报告）
沿用销售策略手册的 **8 部门 × 3 职级**矩阵，报告入口提供角色选择：

| 部门 | 职级 | 关注重心（决定报告强调项） |
|---|---|---|
| 采购 / 供应链 | 执行 / 经理 / 总监 | 成本结构、供应商溢价、让利空间、集采 |
| 研发 / 工程 | 执行 / 经理 / 总监 | 设计优化点、材料替代、可制造性、标准化 |
| 质量 / QA | 执行 / 经理 / 总监 | 质量过度包装、合规、风险，但忌「背锅」式表述 |
| 生产 / 制造 | 执行 / 经理 / 总监 | 工效、工艺路线、良率 |
| 财务 | 执行 / 经理 / 总监 | 总降本额、ROI、账期/资金 |
| 销售 / 业务 | 执行 / 经理 / 总监 | 对客户话术、成交路径、差异化卖点 |
| 高管 / 决策层 | 总监 / VP / C-level | 总降本潜力、战略优先级、投资回报 |
| 客户（品牌方） | 采购 / 研发 / 决策 | 透明化成本、专业感、可谈空间 |

### 6.2 角色决策策略如何作用于多 Agent
在 §5.1 架构中，**全局合成 agent 不是简单合并**，而是在合并前套一层「角色决策策略」：

```
维度策略 agent（并行，各产出原始建议，含所有维度的「素材库」）
   → 全局合成 agent 套「角色决策策略」：
       ① 加重：该角色能拍板/关心的维度置顶强调（如采购→溢价/让利空间）
       ② 弱化：相关但非其职责的维度降权（如研发→财务账期降权）
       ③ 屏蔽/改写：不能或不必出现的
            - 屏蔽：跨部门的敏感归因（如「质量过度包装」对 QA 不直述，改为「设计冗余优化空间」）
            - 改写：技术黑话转该角色语言（如给高管用金额/ROI，给研发用设计参数）
   → 产出「该角色专属、全局一致」的 VAVE 报告
```

### 6.3 角色策略配置结构（可运营调优）
角色决策策略作为**结构化配置**存在（与成本规则同层：算法在代码，策略参数可配）：

```ts
interface RolePolicy {
  role: string;            // 部门+职级
  emphasisDimensions: number[];   // 加重维度（置顶）
  suppressRules: {                 // 屏蔽/改写规则
    dimension?: number;
    keyword?: string;
    action: "hide" | "soften";     // hide=不出现；soften=改写措辞
    reframe?: string;              // soften 时的替代表述
  }[];
  framing: "amount" | "ratio" | "design" | "relationship"; // 表述锚定（金额/占比/设计/关系）
}
```

- **驱动来源**：初始值由《全 KP 岗位销售策略手册》映射而来（§6.1 矩阵）。
- **落点**：MVP 阶段硬化为静态配置（随代码），后续可下沉知识库由运营调优（与「公式=代码、参数=知识库」原则一致）。
- **兜底**：未配 LLM 时，模板层按同一 `RolePolicy` 做确定性裁剪，功能不阻塞。

### 6.4 与成本引擎边界
角色决策策略**只作用于 VAVE 策略层（LLM agents 之上）**，不触及成本计算引擎；维度策略 agent 仍产出全量「素材库」，屏蔽/改写由合成层统一执行——保证同一份客观数据不被污染，只是展示裁剪。

## 9. 技术实现要点

- **复用**：上传/解析/知识库/报告渲染全部现成，VAVE 只叠加分析层。
- **引擎调用**：敏感性重算用修改后的 input 重跑 `runOrchestrator`（全 fan-out 确定性，纯函数可重跑），不单独调 specialist。
- **展示层裁剪**：同一 `AnalysisReport` 经不同「视图选择器」重组，不复制数据。
- **不串 6 specialist 内部 loop**：VAVE 是消费引擎输出的上层模块，遵循 §5.1「禁互调 loop」架构约束。
- **VAVE 多 Agent 编排**：维度策略 agent 并行调用（各自读 `AnalysisReport` + 知识库），结果交全局合成 agent 合并；未配 LLM 时整体回退模板规则（与现有引擎 no-LLM fallback 一致）。
- **面积公式在代码、参数在知识库**：同双面积模型已定架构原则。

## 10. 风险与开放问题

- **前置依赖**：项目实体未建前，VAVE 联动无法实现。需先落地 §4.2（localStorage 版）。
- **精度天花板**：引擎仍为经验合理级（±10%~20%），VAVE 输出敏感度受此约束；真实案例校准（一期未完成项）是结构性前提。
- **KP 角色决策（已定）**：§6 已落地「角色决策策略」完整设计——8 部门×3 职级矩阵、合成 agent 套角色策略做加重/弱化/屏蔽改写、RolePolicy 结构化配置（MVP 静态配置，后续可下沉知识库）。取代原「仅 3 粗粒度视图」的占位项。
- **LLM 多 Agent 成本**：维度策略 agent 并行 + 结果缓存控制调用量；未配 LLM 时模板兜底，功能不阻塞。
- **可追溯性**：VAVE 报告为建议文本，允许 LLM 不确定性，但每维策略须标注数据来源（引回 `AnalysisReport` 的维度金额/占比），保证可审计。
